Brume runs each app in a container whose configuration the engine builds itself, field by field. Containers publish no port, have no Internet access by default, and run with root remapped to an unprivileged user on the host. Options that weaken this isolation can only be turned on in a root-owned file on the host, never from the panel. Static sites are served by a read-only nginx container.

## Container isolation

- **One internal network per environment,** with no Internet access by default. An exposed service also joins an `edge-<service>` network, shared with Traefik only. See [Networking](/docs/how-it-works/networking).
- **No published port.**
- **`userns-remap` on dockerd.** Root in a container maps to an unprivileged UID on the host, so an escape through a runc or kernel flaw does not give root directly. It is turned on at install: turning it on for an existing host means pulling every image again and changing the owner of every volume.
- **Defaults:** `no-new-privileges`, capabilities dropped, and limits on memory, CPU and pids. Without limits, a single container can take Brume down.
- **Default seccomp and AppArmor profiles,** never `unconfined`. The only exception is the builder: see [Builds and deployments](/docs/how-it-works/builds-and-deployments).
- **Configuration built from an allowlist.** The engine sets every field of a container's configuration itself, and copies nothing from a request. A denylist is not enough: several Docker options amount to a host mount, or to joining another container's network.
- **Forbidden unless allowed in [`policy.toml`](#dangerous-options-in-policytoml),** among others:
  - `--privileged`, host network, host mounts, the Docker socket;
  - named volumes with driver options: `o=bind` turns them into a host mount;
  - `--network container:…`, which joins another container's network (joining Traefik's gives access to every edge network);
  - `--volumes-from`;
  - `--pid`, `--ipc`, `--uts` and `--cgroupns` shared with the host or with another container, and `--userns=host`;
  - `--cap-add`, `--device`, `--security-opt`, `--sysctl`, `--runtime`.
- **No access to the tailnet, private ranges, metadata endpoints or Brume.** Brume listens only on unix sockets, on `127.0.0.1` (the API), and on the host's address in the `ingress` network (the webhook), which only `cloudflared` and Traefik reach.

## Dangerous options in `policy.toml`

- **Forbidden options can only be turned on in `/etc/brume/policy.toml`.** Root edits this file over SSH. The panel never can.
- **The engine applies this policy to every request,** whatever the client. A compromised API cannot bypass it.
- **This is the answer for tools that need the Docker socket,** such as Portainer, Watchtower or a CI runner.
- **The Docker socket, `--privileged` and host network also require `--userns=host`.** Docker refuses the last two while the container is remapped, and a remapped root cannot open the socket. With `--userns=host`, root in the container is root on the host again.

## Images

- **The tag is resolved to a digest at deploy time,** and the digest is stored. A rollback redeploys exactly the same image, and a tag changed on the registry does not change production without the admin knowing.
- **Brume's own components** (Traefik, nginx, `cloudflared`, BuildKit) are pinned by digest and updated with every Brume release.

## App secrets

- **Environment variables in 0.1.** Secrets as files on tmpfs come later: see the [roadmap](/docs/how-it-works/roadmap).
- **The engine decrypts them** and injects them when it creates the container. See [Secrets and backups](/docs/how-it-works/secrets-and-backups).

## Databases

- **PostgreSQL, MongoDB and Redis templates:** strong credentials generated by the engine, an app account with minimal rights, and a read-only configuration. See [Templates](/docs/use/templates).
- **Access from your laptop** is over TCP on the tailnet only, through `tailscale serve`, never through a published port. You turn it on database by database. See [Networking](/docs/how-it-works/networking).

## Volumes

- **Deleting a service does not delete its volume right away.** The engine keeps it for a few days.
- **A rollback never restores a volume.** See [Data model](/docs/how-it-works/data-model).

## Static sites

- **An nginx container managed by Brume serves them,** with a read-only volume and a rootless nginx image. Caching, headers and artifact limits are set by the static site template: see [Templates](/docs/use/templates).
- **Hidden files are refused** (`.env`, `.git`), because many builds leave them in the output folder.
- **Artifacts are extracted in an unprivileged process,** never in the engine. Paths containing `../` and symlinks are rejected; otherwise nginx could serve files outside the site.
- **Rollback is instant,** because the latest versions stay on disk. A version can be purged for good, for example if a secret leaked into it. See [Data model](/docs/how-it-works/data-model).

<Callout type="warn" title="Build variables are public">
Every variable the build reads ends up in the JavaScript bundle served to everyone: `VITE_*`, `NEXT_PUBLIC_*`, and anything else the build reads. Brume warns you when a secret is injected into the build of a static site.
</Callout>
