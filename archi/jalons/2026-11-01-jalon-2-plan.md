# Jalon 2 : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `curl -sSL https://brume.dev/install.sh | sudo bash -s -- --domain <zone>` installe Brume sur un VPS vierge, durci (nftables, `userns-remap`, un utilisateur par service). Le panel s'ouvre par Tailscale, et un service reçoit un domaine public servi par Cloudflare Tunnel et Traefik.

**Architecture:** `install.sh` télécharge et vérifie une archive, puis lance `brume install`, qui configure l'hôte en Rust : nftables, Docker, Tailscale, Cloudflare, systemd. Les services tournent en « mode système » (`--system`) : chemins FHS et un utilisateur par service, vérifié sur chaque socket. L'engine ajoute à l'état voulu une `IngressSpec`. L'agent en tire les containers cloudflared et Traefik, leurs réseaux et la config de Traefik.

**Tech Stack:** Rust stable 1.92 (tokio, clap, serde, reqwest, bollard), nftables, systemd, Docker Engine depuis le dépôt apt, Tailscale, API Cloudflare v4, Traefik v3, cloudflared, React (panel), OrbStack (machine Ubuntu 24.04 de test), AWS (ECR Public, EC2).

**Spec:** [`2026-11-01-jalon-2-vps.md`](2026-11-01-jalon-2-vps.md). Lire aussi `archi/base/03-reseau.md`, `04-panel-admin.md`, `05-runtime.md`, `08-hote-et-installation.md`, et le plan du jalon 1 pour les conventions.

## Global Constraints

- Toutes les règles du jalon 1 (« Global Constraints » de [`2026-10-31-jalon-1-plan.md`](2026-10-31-jalon-1-plan.md)) restent valables : `#![forbid(unsafe_code)]`, cœurs sans I/O, `secrecy`, config générée par sérialisation, tailles bornées.
- Gate de fin de tâche : `cargo +nightly fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, et `pnpm run ci` dans `web/` si `web/` change.
- Aucun container ne publie de port. Aucun service de Brume n'écoute ailleurs que sur `127.0.0.1:7878` et des sockets unix.
- Le token API Cloudflare, le token du tunnel et les mots de passe ne sont jamais écrits dans un log, un événement, le bucket, un fichier de l'hôte (sauf le stockage scellé de l'engine) ni une réponse d'API.
- **Aucune tâche déléguée ne crée de ressource AWS,** sauf la tâche 2 (ECR Public). Les EC2 sont créées par le thread principal seulement, une à la fois.
- Les tests sur Linux se font dans la machine OrbStack `brume-e2e` (Ubuntu 24.04, arm64). Une seule tâche à la fois s'en sert ; la tâche qui la casse la recrée (`orb delete -f brume-e2e && orb create ubuntu:noble brume-e2e`).
- Chemins de l'hôte : binaire et `libduckdb.so` dans `/usr/local/lib/brume/`, lien `/usr/local/bin/brume`, données `/var/lib/brume`, sockets `/run/brume`, config `/etc/brume`.
- Plages Docker : `default-address-pools` = `10.213.0.0/17` découpé en `/24`. Réseau `brume-ingress` fixe en `10.213.255.0/24` : Traefik `10.213.255.10`, cloudflared `10.213.255.11`. Pont par défaut de Docker désactivé (`"bridge": "none"`).
- Utilisateurs système : `brume-engine`, `brume-agent` (groupe `docker`), `brume-api`, `brume-telemetry`.

## Review Focus

1. **`brume install` relancé sur un hôte déjà installé** (après un échec à mi-chemin, ou deux fois de suite). Attendu : chaque étape constate ce qui est déjà fait, ne recrée ni tunnel ni utilisateur ni clé maître, et l'install finit. → test dans les tâches 4 et 5.
2. **Le lien Tailscale n'est jamais cliqué, ou HTTPS reste désactivé dans le tailnet.** Attendu : l'install attend au plus 15 minutes en rappelant le lien, puis s'arrête avec un message qui dit comment reprendre (relancer la même commande). → test dans la tâche 5.
3. **Un wildcard `*.<zone>` existe déjà et pointe ailleurs, ou le token Cloudflare n'a pas les droits.** Attendu : l'install refuse avant de créer quoi que ce soit, et nomme le droit ou l'enregistrement en cause. → test dans la tâche 5.
4. **Deux services demandent le même sous-domaine, ou un sous-domaine invalide** (`Demo`, `-x`, `a.b`, 64 caractères). Attendu : refus clair à la mise en attente, rien n'est déployé. → test dans la tâche 6a.
5. **Une requête sans `Tailscale-User-Login`, avec un autre login, ou avec un `Host` qui n'est pas celui de la machine.** Attendu : 403 (ou 421 pour le `Host`) avant toute autre route, panel statique compris. → test dans la tâche 3.

### Task 6a: L'entrée publique : le cœur

**Files:**
- Modify: `crates/brume-domain/src/{names,command,event,decide,evolve,model}.rs`, `crates/brume-proto/src/{admin,agent,api}.rs`, `crates/brume-engine-core/src/{desired,api,staged,queries}.rs`, `crates/brume-engine/src/{shell,sqlite}.rs`, `crates/brume-api/src/routes.rs`, types générés de `web/src/api/`

**Interfaces:**
- Produces (domaine) : newtypes `Zone` (nom DNS, au moins deux labels, minuscules) et `Subdomain` (un label DNS : `[a-z0-9-]`, 1 à 63 caractères, ni début ni fin par `-`). Commande et événement `ConfigureIngress` / `IngressConfigured { zone: Zone, tunnel_id: String }`. Réglage de service `domain: Option<Subdomain>`, porté par le service comme `egress` (`Service.domain`, événement `ServiceDomainChanged { service, domain }`), jamais par la révision : un rollback garde le domaine, dont l'enregistrement DNS existe toujours ([13-modele-de-donnees.md](../base/13-modele-de-donnees.md#révisions)). Mis en attente et déployé par le flux existant (`/api/changes`). Refus, dès la mise en attente : sous-domaine déjà pris par un autre service (tous projets confondus), entrée non configurée, service sans port (port mis en attente compris), retrait du port d'un service qui a un domaine. Un rollback vers une révision sans port est refusé tant que le service a un domaine.
- Produces (proto) : `AdminRequest::ConfigureIngress { zone: String, tunnel_id: String, tunnel_token: SecretString }` → `AdminReply::IngressConfigured`. `PartialEq` écrit à la main comme pour `EnvValue`.
- Produces (proto agent) : `DesiredState.ingress: Option<IngressSpec>` ; `IngressSpec { tunnel_token: SecretString, routes: Vec<IngressRoute> }` ; `IngressRoute { host: String, network: String, target: String, port: u16 }`. Pour chaque service déployé qui a un domaine : un `NetworkSpec` `brume-edge-<service_id>` interne, le container du service y est attaché avec pour alias le nom de ce réseau, et une route `host = <subdomain>.<zone>` (le domaine du service), `network = target = brume-edge-<service_id>`, `port = <port de la révision servie>`. La cible n'est jamais le slug : Traefik est sur tous les réseaux edge, et le DNS de Docker répondrait par le premier service de ce nom, peut-être celui d'un autre environnement.
- Produces (API) : `domain: string | null` dans les réglages d'un service ; `GET /api/ingress` → `{ "zone": string } | null`.
- Le token du tunnel est scellé par la clé maître dans une table à part (`ingress_secrets`), jamais dans un événement.
